### Краткое описание: что делает Redis и зачем нужен TTL
Redis (Remote Dictionary Server) — это высокопроизводительная in-memory система хранения данных типа ключ-значение, которая работает в оперативной памяти, обеспечивая скорость доступа в миллисекунды. TTL (Time-To-Live) — это встроенный механизм, позволяющий автоматически удалять ключи через заданное время, что необходимо для кэширования, чтобы избежать устаревших данных и экономить память. В практике Redis используется для кэширования результатов запросов к основной БД (PostgreSQL), хранения сессий и счётчиков, значительно ускоряя API и снижая нагрузку на основную базу данных.

# Ответы на контрольные вопросы:

- Чем Redis отличается от реляционной БД?

Redis хранит данные в оперативной памяти (in-memory), поэтому доступ к ним намного быстрее, но в случае перезагрузки сервера данные могут быть потеряны (если не настроена персистентность). Реляционная БД (PostgreSQL) хранит данные на диске, что медленнее, но гарантирует их сохранность. Redis работает по принципу ключ-значение без таблиц и SQL, а реляционная БД использует таблицы, строки, столбцы и SQL-запросы. Redis идеален для быстрого кэша и сессий, реляционная БД — для постоянного хранилища структурированных данных.

- Какие типы данных поддерживает Redis кроме строк?

Redis поддерживает: списки (list), множества (set), упорядоченные множества (sorted set), хэши (hash), битовые строки (bitmap), гиперлоги (hyperloglog), геопространственные индексы (geo), потоки (streams). Каждый тип имеет свой набор команд (например, LPUSH/RPOP для списков, SADD/SMEMBERS для множеств).

- Зачем нужен TTL? Приведите примеры.

TTL (Time-To-Live) нужен для автоматического удаления ключей через заданное время, что предотвращает накопление устаревших данных в памяти и экономит ресурсы. **Примеры:** кэш списка товаров обновляется каждые 5 минут, поэтому устанавливается TTL=300 секунд; сессия пользователя должна жить 30 минут, поэтому TTL=1800; одноразовый код подтверждения действует 10 минут, поэтому TTL=600.

- Как Redis помогает снизить нагрузку на PostgreSQL?

Redis используется как кэш между приложением и PostgreSQL: при первом запросе данных из БД они кэшируются в Redis с TTL, а последующие запросы за то же время получают данные из Redis (быстро), не обращаясь к PostgreSQL. Это снижает количество запросов к БД, уменьшает нагрузку на неё и ускоряет ответы API. Например, если список категорий товаров запрашивают 10000 раз в минуту, без кэша это 10000 запросов к БД, с кэшем — только 1 запрос в БД каждые N минут.

- Что произойдёт, если ключ в Redis «протух» по TTL, а приложение попытается его прочитать?

Redis автоматически удалит истёкший ключ, поэтому команда GET вернёт ошибку "redis: nil" (key doesn't exist). В приложении это обработается как кэш-мисс, и код должен заново запросить данные из PostgreSQL и пересохранить их в Redis с новым TTL. Таким образом, приложение всегда гарантирует, что получит актуальные данные.
