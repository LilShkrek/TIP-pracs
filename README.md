### Запуск
Предварительно установить переменную окружения DB_DSN, например:
```bash
export DB_DSN="host=127.0.0.1 user=postgres password=password dbname=pz6_gorm port=5432 sslmode=disable"
```

Зайти в папку `/pz6-gorm` и выполнить:
```bash
go run ./cmd/server
```

### Краткое описание, зачем ORM и чем помог GORM
ORM (Object-Relational Mapping) позволяет работать с базой данных через структуры Go, без ручного написания большинства SQL-запросов, что ускоряет разработку и делает код короче и понятнее. GORM помог автоматически создавать таблицы по моделям (AutoMigrate), описывать связи 1:N и M:N и удобно загружать связанные данные через Preload. Также GORM берет на себя параметризацию запросов, снижает риск SQL-инъекций и упрощает реализацию стандартных CRUD-операций.

# Ответы на контрольные вопросы:

- Что такое ORM и зачем она нужна, если есть database/sql? Приведите 2-3 плюса и 1-2 минуса.

**ORM (Object-Relational Mapping)** — это технология, которая переводит структуры Go в таблицы БД и автоматически генерирует SQL-запросы. **Плюсы:** ускорение разработки (меньше шаблонного SQL кода), автоматическая защита от SQL-инъекций, встроенная поддержка миграций и связей между таблицами. **Минусы:** может быть медленнее ручного SQL на сложных запросах, для оптимизации производительности нужно понимать как ORM генерирует запросы и SQL в целом.

- Как в GORM описать связи 1:N и M:N? Какие теги на полях вы использовали?

**1:N:** слайс в родительской структуре (`Notes []Note` в User) и внешний ключ в дочерней (`UserID uint` в Note). **M:N:** слайсы в обеих структурах с тегом `gorm:"many2many:таблица_связи;"` (например, `Tags []Tag` в Note с тегом `many2many:note_tags` и `Notes []Note` в Tag с аналогичным тегом).

- Что делает AutoMigrate? В каких случаях его недостаточно?

**AutoMigrate** автоматически создаёт или обновляет таблицы по структурам Go. Для каждой модели создаст таблицу со всеми указанными полями, индексами и ограничениями. **Недостаточно для:** сложных миграций (удаление полей, изменение типов данных), специфичных индексов и ограничений, развёртывания на production без контроля версий схемы.

- Чем Preload отличается от обычного Find/First? Когда его применять?

**Preload** явно загружает связанные данные в один запрос (через JOIN), а без него связи будут nil или пусты (lazy loading). **Применяйте когда:** нужны данные автора заметки или её теги вместе с самой заметкой одним запросом, иначе без Preload потребуется отдельный запрос для каждой связи (N+1 queries проблема).

- Как в GORM обработать ошибку нарушения уникального индекса? Что вернёт БД/драйвер?

**Ошибка:** `ERROR: duplicate key value violates unique constraint`. Обработать можно через `if err := db.Create(...).Error; err != nil { /* проверяем строку ошибки или используем обработчик */ }`. GORM пробросит исходную ошибку от PostgreSQL, которая содержит имя индекса и детали нарушения.
